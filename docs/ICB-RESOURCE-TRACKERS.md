## Where the tokens came from

**Every token above was read out of a real `Inventory:` / `Lockbox:` line in Baby's own Palia
Assistant logs** (app-20260807, app-20260809, app-20260818), on 2026-08-19. None was guessed from
an item name. A guessed token is worse than a missing card: it sits at zero all stream and looks
like a bug.

Two traps worth remembering:

- **Gold Ore is `itemtype_mineral_ore_gold`, not `itemtype_currency_gold`.** The currency token
  appears 606 times in the logs and the ore only 11 — picking the popular one would have made the
  card count Baby's money. A test asserts a 500-gold pickup does not move the Gold Ore card.
- **Dragon's Beard Peat is `itemtype_forage_moss_dragonsbeard`** — the word "peat" is not in the
  token at all, so searching for it finds nothing.

Adding a card later means catching the item once and taking the token from the log line.

## Reset behaviour

Amber Echo and Infected Essence are **lifetime** (Baby's decision, 2026-08-16). They do not count
separately — they mirror the existing reconciled totals in `live.resources`, so there is exactly one
number per resource and the reconciliation controls still own it. The dashboard refuses to edit them
directly and points at the reconciliation panel instead.

Everything else is **session**: zeroed automatically when Baby logs into Palia, detected from
`MAP_IntroMovie` / `MAP_PreGame`. Those two strings appear only at game startup — `app-20260818.log`
contains no other `MAP_` value at all, so zone travel cannot trigger it.

**Every reset is undoable.** Baby logged into Palia **11 times on 2026-08-18**, so a silent wipe is
a real risk, not a theoretical one. The previous values are kept and the dashboard shows an
**Undo — put the numbers back** button. Repeat login lines inside a two-minute window are treated as
one login, so a single startup cannot fire several resets and destroy the undo.

## Value boxes

Each card declares its own `valueBox` in `config/resource-trackers.json`, as a percentage of that
card's image. They were measured from the artwork by dark-plus-flat detection and then checked
visually with the box outlined on every card. **If a card is re-exported, re-measure it.**

A test fails the build if a box falls outside its artwork, if two cards claim the same token, if a
token is malformed, if artwork is missing, or if a card page stops shipping its `<img>` in the HTML.

## Files

| Path | What it is |
| --- | --- |
| `assets/resources/` | The card artwork |
| `config/resource-trackers.json` | Tokens, modes, value boxes |
| `data/resource-trackers.json` | The counts. Back this up. |

The pages are generated by `renderResourceCardPage` in `server.js`, on the deliberately plain
pattern proven to render in Meld — image in the static HTML, plain ES5, XHR poll that only
rewrites the number. **Do not modernise them**, and do not add a query string to a Meld URL.
